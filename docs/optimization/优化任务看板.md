# CodeAgent 优化任务看板

> 本文档用于 `docs/codex/plans.md` 之后的优化阶段管理。正式里程碑计划已完成，后续不再把体验修复和质量加固追加为新的 Milestone，而是在这里登记、跟踪和归档。

## 管理规则

- `plans.md` 保持为原始里程碑事实来源，不再追加优化 Milestone。
- 每个优化任务使用 `OPTxx` 编号，并在 `docs/dev_reports/` 中形成独立汇报。
- 每个优化任务必须记录：问题、影响、修复范围、验证命令、结论。
- 涉及真实 LLM 的验证默认只跑 1 个自建 benchmark case，除非明确需要全量验收。

## OPT01 摘要

- wizard 新增审批模式选择，默认人工审批，可切换为自动审批。
- 自动审批会明确记录为 `decision_source=user_configured_auto`，benchmark 自动审批记录为 `benchmark_auto`。
- implementation 阶段禁止生成测试文件，testing 阶段必须生成真正测试用例。
- 每个 run 新增 `workflow.log` 和 `workflow_events.jsonl`，记录 LLM prompt/response、审批、路由、阶段结果和命令结果。

## OPT02 摘要

- 计划审批收敛为两个选项：同意，或不同意并提出修改意见让 Agent 重新生成。
- 实现阶段新增独立的 ImplementationPlan 审批点，批准后才会生成和应用实现补丁。
- testing 阶段选择“提出修改意见”不再被当作测试失败，也不会误入 debug/repair；系统会记录 `respond` 决策并重新生成测试方案。
- 人工审批 UI 改为中文选择题；补丁和命令这类副作用审批仍保留拒绝、取消等风险控制选项。

## OPT03 摘要

- `ImplementationPlan`、`TestingPlan`、`RepairPlan` 改为纯计划 schema，拒绝完整文件内容、diff、`old_content/new_content`。
- 新增 `ImplementationPatchDraft`、`TestingPatchDraft`、`RepairPatchDraft`，只在计划通过后由第二次 LLM 调用生成。
- repair 阶段补齐修复计划审批点，并让 `respond` 在计划审批时重新生成计划、在补丁审批时重新生成补丁草案。
- CLI 审批前会打印已经真实落盘的计划文件、补丁文件和可审查项目文件，展示格式为 `文件名 (相对路径)`；尚未创建的计划目标不会被打印成可点击文件。
- `workflow.log` 和 `workflow_events.jsonl` 区分记录 `plan_generation` 与 `patch_generation`。

## OPT04 摘要

- 计划审批文案统一为“实施此实现/测试/修复计划？”，只提供“是，实施此计划”和“否，告知 CodeAgent 如何调整”两个选项。
- 实现、测试、修复补丁审批统一为“应用此实现/测试/修复补丁？”，只提供“是，应用此补丁”和“否，告知 CodeAgent 如何调整”两个选项。
- 调试阶段进入时会显示失败证据来源、是否重跑复现命令；完成时显示复现状态、置信度、首要嫌疑文件和 `debug_report.md`。
- 修复阶段每次回归验证都会显示命令执行状态和 `[测试结果] passed/failed/errors/skipped/total`，失败时同步提示 `repair_test_result.json` 和 `repair_report.md`。
- `workflow.log` 新增 `debugging_attempt_started` / `debugging_attempt_finished`，用于区分多轮调试。

## OPT05 摘要

- 从真实 Todo Manager 半交互运行中定位到一类问题：testing 阶段生成的 CLI/subprocess 测试脚手架把 `PROJECT_ROOT` 错拼为 `parent.parent / "project"`，导致所有 CLI 测试在 `subprocess.run(cwd=...)` 前置阶段失败。
- testing 阶段新增测试补丁质量门，若发现生成测试把 `__file__` 父目录再拼接硬编码 `project/workspace` 作为 cwd 或 sys.path 根，会在应用补丁前失败，提示重新生成测试。
- debugging 阶段新增“生成测试脚手架缺陷”识别：遇到 `NotADirectoryError` / `WinError 267` / `No such file or directory` 且 traceback 来自生成测试的 `subprocess cwd` 时，停止进入 repair，避免为了坏测试修改产品代码。
- PlanGenerationService 的 TestingPatchDraft prompt 增加 cwd 约束，要求 CLI/subprocess 测试从真实项目根目录运行，禁止硬编码嵌套 `project/workspace`。
- 修复 Windows 路径归一化细节，确保 `tests\test_cli.py` 这类路径仍能进入测试内容质量检查。

## OPT06 摘要

- `codeagent wizard` 默认切换为 Codex 风格 `prompt_toolkit` TUI：非全屏、表单固定在终端中原地更新，字段选项在当前字段下方内联展开，而不是跳到新页面或折叠小标题。
- 表单支持按任意顺序编辑基础设置、输入材料、运行策略、模型与审批、最终确认；输入材料支持多选和手动补充路径。
- wizard 新增模型选择字段，默认 `anthropic/claude-sonnet-4.6`，并提供 Anthropic Opus、OpenAI、Gemini、DeepSeek、MiniMax、Qwen 等固定候选；选择结果写入 `task_config.yaml`。
- 新增 `TuiApprovalConsole` 和 `TuiProgressReporter`，wizard 运行中的计划/补丁/命令审批与阶段进度使用同一套底部选择和滚动记录风格；非 TTY 环境使用脚本式行输入，真实 TTY 中的 TUI 初始化错误会直接暴露，便于定位环境问题。
- `execute_task_config` 支持注入审批控制台，普通 `run/benchmark` 默认行为保持不变。

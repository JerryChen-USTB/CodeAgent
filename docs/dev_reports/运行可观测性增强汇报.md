# 运行可观测性增强汇报

## 背景

在 VS Code 插件验收 Todo Manager 案例时，工作流最终成功，但运行审查暴露出两个可观测性问题：

- Windows 下 `llm_calls` 子目录名过长，使用普通 PowerShell 递归扫描时可能出现 `Could not find a part of the path`，误导排查。
- `final_report.md` 能说明阶段结果，但缺少一份机器可读的一页式健康摘要，审查者需要手动交叉读取 `workflow_events.jsonl`、`stage_result.json`、测试结果和审批记录。

## 本次改动

### 新增运行健康摘要

新增模块：

- `codeagent/cli/inspect_run.py`

新增产物：

- `run_health.json`
- `run_health.md`

每次 `execute_task_config()` 结束后会自动生成上述文件，并注册到 `artifacts_index.json`。如果健康摘要生成失败，只会写入 `run_health_summary_failed` 事件，不影响真实任务结果。

健康摘要包含：

- 最终状态与健康状态。
- 阶段状态、阶段开始事件、阶段结果事件。
- 路由路径。
- LLM prompt/response/structured output/retry/invalid/model error 统计。
- 审批请求与审批决策统计。
- 测试阶段与修复阶段测试结果。
- JSONL 校验问题。
- Windows 长路径风险。
- 已失败但后续被调试/修复恢复的阶段提示。

### 新增 CLI 诊断命令

新增命令：

```powershell
python -m codeagent inspect-run --run-dir <run_dir>
```

常用参数：

```powershell
python -m codeagent inspect-run --run-dir <run_dir> --no-write
python -m codeagent inspect-run --run-dir <run_dir> --json
```

该命令可用于历史运行目录，即使该运行并不是新版 CodeAgent 生成的，也能从已有产物中回收诊断信息。

### 缩短 LLM 调用目录名

新运行中的 `<stage>/llm_calls/` 子目录改为短目录名：

```text
001_single_file_patch_generation__ImplementationPatchDraft__<hash>
```

完整语义信息保留在该目录的 `request.json` 中：

- `call_label`
- `schema`
- `generation_kind`
- `audit_filename`
- `prompt_sha256`
- `prompt_chars`

这样既降低 Windows 长路径风险，也不牺牲审计可追踪性。

### VS Code 桥接增强

`vscode-run` 的 `run_completed` JSONL 事件新增：

- `run_health_path`
- `run_health_report_path`

后续 Webview 可以直接用这两个路径展示“运行诊断”入口。

## 已验证结果

对真实运行目录执行：

```powershell
python -m codeagent inspect-run --run-dir D:\Projects\CodeAgent\codeagent_runs\demos\todo_manager\vscode_20260611_145711\interactive\runs\2026-06-11_065824_248185_implement-test-debug-repair_310020
```

输出摘要显示：

- 最终状态：`succeeded`
- 实现阶段：`succeeded`
- 测试阶段：`failed`
- 调试阶段：`succeeded`
- 修复阶段：`succeeded`
- LLM：`prompts=14, responses=14, retries=0, invalid=0`
- 测试：测试阶段 `91/93 passed`，修复后 `93/93 passed`
- 警告：测试失败后被修复恢复；历史 run 存在长路径风险

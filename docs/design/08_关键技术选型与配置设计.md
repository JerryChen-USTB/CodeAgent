# 08 关键技术选型与配置设计

## 1. 技术栈总览

| 层 | 技术选择 | 作用 |
|---|---|---|
| 编程语言 | Python 3.11+ | 实现 CLI、LangGraph/LangChain 工作流、工具和报告 |
| 工作流编排 | LangGraph | 主图、阶段子图、状态流转、checkpoint、interrupt、streaming |
| 模型与工具 | LangChain | OpenAI-compatible 模型调用、tool 抽象、结构化输出、HITL middleware |
| 模型服务 | OpenRouter OpenAI-compatible API | 临时使用 `google/gemini-3.5-flash`，不写死 OpenRouter SDK |
| Checkpoint | SQLite + LangGraph SQLite checkpointer | 本地可恢复、适合课程原型 |
| 测试框架 | pytest | MVP 唯一支持测试框架 |
| CLI | Typer + Rich，或 argparse + Rich | wizard、命令模式、进度显示、审批 UI |
| 配置 | YAML/JSON + Pydantic | task.yaml、benchmark.yaml、模型配置校验 |
| patch | unified diff + 自研 PatchService | 不依赖 Git 工作区检查 |
| 日志/报告 | Markdown + JSON/JSONL | 可读报告和机器可读结果 |

## 2. LangGraph 选型理由

LangGraph 作为底层编排框架，适合本项目的原因：

1. 系统是长时间运行、有状态的 Agent，而不是一次性模型调用；
2. 实现、测试、调试、修复之间存在条件路由；
3. 测试失败后需要进入调试，修复失败后需要回到调试/修复闭环；
4. 测试方案、patch、测试命令需要 HITL interrupt；
5. 运行过程需要 checkpoint 和 resume；
6. CLI 需要实时显示节点进度和工具调用。

具体使用方式：

```python
builder = StateGraph(AgentState)
builder.add_node("implementation", implementation_subgraph)
builder.add_node("testing", testing_subgraph)
builder.add_node("debugging", debugging_subgraph)
builder.add_node("repair", repair_subgraph)
builder.add_conditional_edges("testing", route_after_testing)
graph = builder.compile(checkpointer=sqlite_checkpointer)
```

## 3. LangChain 选型理由

LangChain 在本项目中不作为完整业务框架，而作为模型和工具调用基础设施：

1. 统一 ChatModel 接口，便于 OpenAI-compatible 接入；
2. 用 tool 抽象注册文件、搜索、patch、shell 等工具；
3. 用结构化输出约束计划、测试方案、故障定位、修复计划；
4. 用 HumanInTheLoopMiddleware 对有副作用工具做兜底审批；
5. 用 prompt 和 middleware 管理不同角色节点行为。

## 4. 模型接入设计

### 4.1 配置原则

模型接入不写死 OpenRouter SDK，而使用 OpenAI-compatible 参数：

```yaml
model:
  provider: openai_compatible
  model_name: google/gemini-3.5-flash
  base_url: https://openrouter.ai/api/v1
  api_key_env: OPENROUTER_API_KEY
  temperature: 0.2
  timeout_seconds: 120
  max_retries: 2
  max_tokens: 16384
```

### 4.2 Python 初始化草案

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model=config.model.model_name,
    base_url=config.model.base_url,
    api_key=os.environ[config.model.api_key_env],
    temperature=config.model.temperature,
    timeout=config.model.timeout_seconds,
    max_retries=config.model.max_retries,
)
```

### 4.3 模型参数策略

| 参数 | 默认值 | 理由 |
|---|---:|---|
| temperature | 0.2 | 代码和结构化输出需要稳定性 |
| max_retries | 2 | 处理临时 API/结构化输出错误，避免无限重试 |
| timeout_seconds | 120 | 代码任务响应较长，需要高于普通聊天 |
| max_tokens | 16384 | 避免 OpenRouter 对大默认输出窗口预占过高预算，同时仍可按任务配置覆盖 |

## 5. SQLite checkpoint 选型

SQLite 适合本课程原型：

| 维度 | 说明 |
|---|---|
| 本地运行 | 不需要额外数据库服务 |
| 可恢复 | 能用 run_id/thread_id 恢复 interrupt 后状态 |
| 可检查 | checkpoint 文件随输出目录保存，便于复现 |
| 复杂度 | 比 Postgres 更低，适合课程设计 |
| 局限 | 不适合高并发生产部署，但本项目不追求多用户并发 |

建议依赖：

```text
langgraph
langgraph-checkpoint-sqlite
```

初始化草案：

```python
import sqlite3
from langgraph.checkpoint.sqlite import SqliteSaver

conn = sqlite3.connect(run_dir / "checkpoints.sqlite", check_same_thread=False)
checkpointer = SqliteSaver(conn)
graph = builder.compile(checkpointer=checkpointer)
config = {"configurable": {"thread_id": run_id}}
```

## 6. Python + pytest 选型

MVP 只支持 Python + pytest，理由：

1. 课程重点是 Agent 工作流和工具调用，不是多语言平台；
2. Python 项目便于构造小型 benchmark；
3. pytest 输出格式相对稳定，便于解析通过数、失败数和失败用例；
4. 修复验证可以统一使用 `pytest -q`；
5. Java 后续可通过 `LanguageAdapter` 和 `TestFrameworkAdapter` 扩展。

默认命令：

```yaml
test_framework: pytest
test_command: pytest -q
```

## 7. CLI 技术选型

推荐：Typer + Rich。

| 技术 | 用途 | 可替代方案 |
|---|---|---|
| Typer | 子命令、参数、帮助信息 | argparse |
| Rich | 彩色进度、表格、Markdown 片段、审批提示 | 普通 print |
| PyYAML | 读取 task.yaml/benchmark.yaml | ruamel.yaml/json |
| Pydantic | 配置和结构化输出校验 | dataclasses + 手写校验 |

CLI 命令：

```bash
codeagent --help
codeagent wizard
codeagent run --config task.yaml
codeagent implement --project ./repo --requirements requirements.md
codeagent test --project ./repo --test-cmd "pytest -q"
codeagent debug --project ./repo --test-cmd "pytest -q" --log failing.log
codeagent repair --project ./repo --test-cmd "pytest -q"
codeagent benchmark --config benchmark.yaml
codeagent resume --run-id <run_id>
```

## 8. 配置文件设计

### 8.1 task.yaml

```yaml
task_id: login_feature_001
mode: run
stages: [implement, test, debug, repair]
project_path: ./examples/login_project
output_dir: ./codeagent_runs
language: python
test_framework: pytest
test_command: pytest -q

input_materials:
  - material_type: requirements
    path: ./requirements.md
    required: true
  - material_type: acceptance
    path: ./acceptance.md
    required: false

model:
  provider: openai_compatible
  model_name: google/gemini-3.5-flash
  base_url: https://openrouter.ai/api/v1
  api_key_env: OPENROUTER_API_KEY
  temperature: 0.2
  timeout_seconds: 120
  max_retries: 2

runtime:
  checkpoint: sqlite
  max_repair_attempts: 3
  command_timeout_seconds: 120
  log_truncation_chars: 12000
  auto_approve_in_benchmark: false

permissions:
  require_approval_for:
    - test_plan
    - patch_apply
    - shell_command
  skip_sensitive_files: true
```

### 8.2 benchmark.yaml

```yaml
benchmark_id: course_design_benchmark_v1

model:

```

## 10. 不采用方案说明

| 不采用方案 | 原因 |
|---|---|
| 复杂多 Agent 团队框架 | 增加不确定性，不利于课程演示和调试 |
| 直接写文件 | 无法满足 patch-first 和人工审批 |
| Git 工作区检查 | 用户明确不考虑，且会给非 Git 项目带来不必要复杂度 |
| IDE 插件 | 当前项目范围不包含 IDE；专注 CLI 原型 |
| 多语言同步支持 | 超出课程原型主线，先以 Python + pytest 做深做稳 |
| 生产级容器沙箱 | 课程项目不以生产安全为重点，但保留命令审批和路径限制 |

## 11. 版本兼容建议

# 待办事项管理系统 PRD

## 1. 产品目标

提供一个轻量、可离线使用的个人待办事项 CLI，使用户能够在不打开图形界面的情况下完成任务记录和状态维护。

## 2. 用户画像

- 主要用户：学生、开发者、课程项目成员。
- 使用环境：Windows / Linux / macOS 终端。
- 使用频率：每天多次，单次操作应快速完成。

## 3. 核心价值

- 快速记录任务。
- 明确区分未完成和已完成任务。
- 用本地 JSON 文件保存数据，便于备份和检查。
- 输出稳定，便于脚本或测试读取。

## 4. 功能范围

| 编号 | 功能 | 优先级 | 描述 |
| --- | --- | --- | --- |
| F1 | 添加任务 | P0 | 创建包含标题、截止日期、优先级和状态的任务 |
| F2 | 查看任务 | P0 | 按状态过滤并按 ID 升序显示任务 |
| F3 | 完成任务 | P0 | 将指定任务状态改为 done |
| F4 | 删除任务 | P0 | 从任务文件中移除指定任务 |
| F5 | 数据持久化 | P0 | 所有变更写入 JSON 文件 |
| F6 | 输入校验 | P0 | 拒绝空标题、错误日期和不存在的任务 |

## 5. 非目标

- 不做多用户权限。
- 不做网络同步。
- 不做循环任务和提醒通知。
- 不做图形界面。

## 6. 关键业务规则

- 每个任务 ID 在一个文件内唯一。
- 删除任务后，后续新增任务不能复用已删除 ID，仍使用最大 ID 加一。
- `done` 操作必须持久化。
- `list --status open` 只显示未完成任务。
- `list --status done` 只显示已完成任务。

## 7. 验收摘要

产品验收以隐藏测试为准。只要 CLI 输出、JSON 数据、错误处理和状态流转满足文档，即视为通过。

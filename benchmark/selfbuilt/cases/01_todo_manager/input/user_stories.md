# 待办事项管理系统用户故事

## US-01 启动一个真正的交互式会话

作为个人用户，我希望只启动一次待办事项管理系统，就能看到清晰的文本菜单，这样我可以连续管理多个任务，而不是每做一步都重新输入一条 shell 命令。

当我运行 `python -m todo_manager --file tasks.json` 时，我希望程序显示产品名称、当前使用的数据文件和可选操作。我可以输入 `1` 添加任务，输入 `2` 查看任务，输入 `3` 标记完成，输入 `4` 删除任务，输入 `5` 退出。完成某个动作后，程序应回到主菜单，直到我主动退出。

验收要点：

- 默认启动方式会进入交互式菜单。
- 添加、查看、完成、删除、输入错误后，会话仍继续运行。
- 可以通过 `5`、`q`、`quit` 或 `exit` 退出。
- 菜单使用普通文本输入输出，能被自动化脚本驱动。

## US-02 通过引导式提示添加任务

作为正在安排当天任务的学生，我希望系统逐步询问任务标题、截止日期和优先级，这样我不需要记住复杂命令参数。

例如，我在菜单中选择添加任务，输入标题 `Write report`，输入截止日期 `2026-06-10`，输入优先级 `high`。系统应确认创建了 `#1` 任务，并返回菜单。如果我添加 `Buy milk` 时截止日期和优先级都直接回车，系统应将截止日期视为无，将优先级设为 `normal`。

验收要点：

- 空优先级表示 `normal`。
- 空截止日期表示无截止日期。
- 成功提示包含任务 ID 和标题。
- 新任务 ID 从 `1` 开始，并按当前最大 ID 加一。
- 同一个会话中可以连续添加多个任务。

## US-03 在不丢失上下文的情况下查看任务

作为有多个待办事项的用户，我希望可以查看全部任务，也可以只查看某个状态的任务，这样我能专注于当前仍需处理的事项。

我在菜单中选择查看任务后，系统询问状态过滤条件。如果我直接回车或输入 `all`，系统显示全部任务；如果输入 `open`，只显示未完成任务；如果输入 `done`，只显示已完成任务。每条任务应展示 ID、状态、优先级、标题和截止日期。

验收要点：

- 空过滤条件和 `all` 都表示全部任务。
- `open` 和 `done` 只显示匹配任务。
- 没有任务或没有匹配任务时输出 `no tasks`。
- 每条任务按文档格式稳定输出。

## US-04 完成任务并保存进度

作为完成某项工作的用户，我希望把任务标记为已完成，并立即保存状态，这样我关闭程序后再次打开时仍能看到它已经完成。

我在菜单中选择标记完成，输入任务 ID，系统输出类似 `completed task #1: Write report` 的确认信息。随后我查看 done 任务列表，应能看到该任务。如果我退出程序，再用同一个数据文件重新打开，任务仍应保持 `done` 状态。

验收要点：

- done 状态会持久化到 JSON 文件。
- 对已经完成的任务再次执行完成操作仍然成功。
- 不存在或非法 ID 会输出 `task not found`，不会打印 traceback。

## US-05 删除不再需要的任务

作为希望保持任务列表简洁的用户，我希望从交互式菜单删除不再需要的任务。

我选择删除任务，输入一个存在的任务 ID，系统确认删除了哪个任务。之后查看任务列表时，该任务不再出现。删除操作应立即写入 JSON 文件。后续新增任务时，系统应根据当前文件中的最大 ID 继续分配 ID，保证行为确定。

验收要点：

- 删除操作会从 JSON 中移除任务。
- 删除确认信息包含任务 ID 和标题。
- 不存在或非法 ID 会输出 `task not found`。
- 新增任务 ID 分配规则稳定可预测。

## US-06 在输入错误后继续使用

作为快速输入数据的用户，我希望系统能告诉我哪里错了，并继续运行，而不是因为一次错误输入就退出。

如果我添加任务时输入空标题，系统应提示 `title is required` 并回到菜单。如果我输入 `2026/06/10` 这样的日期，系统应提示 `invalid due date`。如果我输入 `urgent` 作为优先级，系统应提示 `invalid priority`。如果查看任务时输入非法状态过滤值，系统应提示 `invalid status`。如果输入未知菜单项，系统应提示 `unknown option`。

验收要点：

- 校验失败不会写入半成品任务。
- 校验失败不会导致程序崩溃。
- 校验失败后会返回菜单，继续接受下一个操作。

## US-07 理解损坏的数据文件

作为可能手动编辑 JSON 文件的用户，我希望数据文件损坏时收到明确错误，这样我能知道问题来自任务文件，而不是程序卡住。

如果指定的数据文件存在但不是合法 JSON，程序不应进入菜单，也不应覆盖这个文件。它应以非 0 退出码结束，并在 stderr 中输出 `invalid task file`。

验收要点：

- 启动时检测非法 JSON。
- 错误信息包含 `invalid task file`。
- 程序不会覆盖损坏的数据文件。

## US-08 支持自动化评测驱动

作为课程评测者，我希望能通过 stdin 发送多行菜单选项和输入内容，这样 benchmark 可以验证真实交互体验，而不需要人工操作。

程序不应要求鼠标、方向键控制序列、raw terminal mode 或全屏终端。简单的重复文本菜单即可。程序应读取普通文本行，输出普通文本结果，并在收到退出选项或 EOF 后正常退出。

验收要点：

- `subprocess.run(..., input=<多行脚本>)` 可以驱动应用。
- 脚本输入结束后进程不会挂起。
- 隐藏 oracle 可以检查 stdout、stderr、退出码和 JSON 持久化结果。

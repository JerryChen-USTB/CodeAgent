# 会议室预约系统用户故事

## US-01 在浏览器中打开会议室预约系统

作为团队成员，我希望管理员在本机启动 Flask 服务后，可以直接用浏览器打开系统首页，而不是只能通过命令行或手动 HTTP 请求操作。

首页应显示 `会议室预约系统`，并提供会议室管理和预约管理入口。演示人员应能在浏览器中完成创建会议室、创建预约、筛选预约和取消预约。

## US-02 行政管理员创建会议室

作为行政管理员，我希望在会议室管理页面录入会议室：

- 名称：`Room A`
- 容量：`8`
- 位置：`2F`

提交后，页面应显示 `Room A`，JSON API `GET /rooms` 也能返回这间会议室。若我再次创建同名会议室，系统应拒绝并显示 `room already exists`。

## US-03 员工创建会议预约

作为普通员工，我希望在预约页面选择会议室，填写预约人、标题、开始时间和结束时间。例如：

- 会议室：`Room A`
- 预约人：`Ada`
- 标题：`Weekly Sync`
- 开始：`2026-06-10 09:00`
- 结束：`2026-06-10 10:00`

提交后，页面应显示 `Weekly Sync`、`Ada` 和时间段。JSON API 创建预约时应返回状态为 `active` 的预约对象。

## US-04 避免会议室时间冲突

作为员工，我希望系统阻止同一会议室的重叠预约。若 `Room A` 已有 `09:00-10:00` 的 active 预约，再创建 `09:30-10:30` 应显示 `booking conflict`。

如果新预约刚好从 `10:00` 开始，则边界相接，不应算冲突。另一个会议室在同一时间段也可以预约。

## US-05 查看某天或某会议室的预约

作为团队成员，我希望在预约页面按日期 `2026-06-10` 和会议室筛选 active 预约。列表应按开始时间升序展示，便于快速了解一天的占用情况。

已取消预约不应出现在列表中。

## US-06 取消预约并释放时间段

作为员工，如果会议取消，我希望可以在 Web UI 中取消预约。取消成功后，该预约从查询列表中消失。

取消后的时间段应被释放。也就是说，原来因冲突被拒绝的同时间段预约，在取消旧预约后可以重新创建。

## US-07 使用 JSON API 集成

作为自动化脚本或其它系统，我希望仍能通过 JSON API 创建会议室、创建预约、查询预约和取消预约。

API 错误必须返回 JSON，例如 `{"error": "room not found"}` 或 `{"error": "booking conflict"}`，不能返回 Python traceback。

## US-08 拒绝错误输入

作为使用者，我希望系统明确拒绝错误数据：

- 空会议室名称或空预约标题显示 `missing field`。
- capacity 小于等于 0 显示 `invalid capacity`。
- start 晚于或等于 end 显示 `invalid time`。
- 不存在的会议室显示 `room not found`。
- 已取消或不存在的预约再次取消显示 `booking not found`。

# 图书借阅管理系统用户故事

## US-01 在浏览器中打开本地图书管理系统

作为图书管理员，我希望在本机运行 `python -m library_lending --db library.db --host 127.0.0.1 --port 8000` 后，可以在浏览器打开 `http://127.0.0.1:8000/` 使用系统。

首页应显示 `图书借阅管理系统`，并让我清楚看到添加图书、注册读者、借书、还书、查看库存和查询逾期这些入口。我不希望每次操作都重新输入一条 shell 命令，也不希望手动发送 HTTP 请求。

## US-02 添加图书并查看库存

作为管理员，我希望通过页面表单录入一本书。例如：

- ISBN：`978-1`
- 书名：`Clean Code`
- 作者：`Robert Martin`
- 册数：`2`

提交后，页面应告诉我 `book 978-1 available copies: 2`。随后我进入库存页，应看到：

```text
978-1 Clean Code by Robert Martin copies 2 available 2
```

如果同一个 ISBN 后续又入库 1 册，系统应增加总册数，而不是创建重复图书。

## US-03 注册读者

作为管理员，我希望通过表单注册读者。例如读者编号 `r1`，姓名 `Ada`。提交后页面应显示：

```text
reader r1 registered
```

如果我再次使用同一个读者编号注册，系统应更新姓名，不创建重复读者。这样后续借阅记录可以稳定关联到同一个读者编号。

## US-04 为读者办理借书

作为管理员，我希望在浏览器中填写读者编号、ISBN 和借出日期，为读者办理借书。例如读者 `r1` 在 `2026-06-01` 借阅 `978-1`。

系统应检查读者存在、图书存在、仍有可借副本，并计算应还日期为借出日期后 14 天。借书成功后页面应显示：

```text
borrowed 978-1 by r1 due 2026-06-15
```

此时再查看库存，应看到可借数量从 2 变为 1。

## US-05 防止重复借阅和超库存借阅

作为管理员，我希望系统保护库存数据。若同一读者已经借了某本书且尚未归还，再次借同一本书时，页面应显示 `already borrowed`。

如果某本书所有副本都已借出，其他读者再借时，页面应显示 `no available copies`。这些错误不应破坏已有数据库，也不应让库存变成负数。

## US-06 办理还书并恢复库存

作为管理员，我希望通过表单输入读者编号、ISBN 和归还日期，为读者办理还书。归还成功后页面应显示：

```text
returned 978-1 by r1
```

还书后库存页中的 available 数量应恢复。如果再次归还同一本已经归还的书，系统应显示 `loan not found`。

## US-07 查询逾期借阅

作为班级负责人，我希望输入一个当前日期，例如 `2026-06-20`，查看所有已过应还日期但尚未归还的借阅。

如果 `r1` 在 `2026-06-01` 借书，due date 是 `2026-06-15`，那么在 `2026-06-20` 查询逾期时应看到：

```text
r1 978-1 due 2026-06-15
```

如果这本书已经归还，再次查询应显示：

```text
no overdue loans
```

## US-08 拒绝错误输入

作为管理员，我希望系统明确拒绝错误数据。例如：

- 册数为 `0` 或负数时，显示 `invalid copies`。
- 日期写成 `2026/06/01` 时，显示 `invalid date`。
- 未注册读者借书时，显示 `reader not found`。
- 不存在的 ISBN 被借阅时，显示 `book not found`。

这些错误应显示在浏览器页面中，而不是只写到终端 stderr。

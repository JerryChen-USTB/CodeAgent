# 个人记账系统 PRD

## 1. 产品概述

个人记账系统是一款面向个人用户的本地离线记账软件。用户可以在终端里连续记录收入和支出，查看流水明细，按月份统计收入、支出、余额和分类支出，并对错误账目进行编辑或删除。产品第一版不追求联网、多账本、图表或复杂预算功能，而是强调“启动一次程序，在同一个会话里完成多次记账操作”的真实软件体验。

本案例要求智能体从空 `workspace/` 开始实现完整 Python 项目。最终成品必须像正常软件一样可交互使用：用户运行一次 `python -m personal_ledger --file ledger.json` 后进入简单文本 TUI 菜单，通过菜单、表单、列表和确认提示完成记账。成品不能只依赖“一次一个 shell 命令”的脚本，也不能要求用户手动发送 HTTP 请求。

## 2. 产品目标

- 支持个人用户在一个连续终端会话中新增、查询、统计、编辑和删除账目。
- 使用本地 UTF-8 JSON 文件保存账本数据，保证关闭程序后再次打开仍能加载历史账目。
- 使用菜单和表单降低命令记忆成本，让用户像使用普通小工具一样操作软件。
- 支持标准输入驱动，便于真实用户手动输入，也便于自动化 oracle 测试通过 subprocess 模拟操作。
- 金额计算必须可靠，避免浮点误差，所有金额展示和保存均保留两位小数。
- 仅使用 Python 3.11+ 标准库实现，保证评测环境准备简单。

## 3. 用户画像

### 3.1 每天记录消费的上班族

用户每天会记录午餐、交通、咖啡、购物等支出，也会偶尔记录工资、报销等收入。用户希望打开程序后，不用记住复杂命令参数，只需选择“新增账目”，按提示填写日期、类型、分类、金额和备注即可。月底时，用户希望快速查看本月总收入、总支出、余额，以及 food、transport、shopping 等支出分类分别花了多少钱。

### 3.2 需要复盘现金流的学生

学生每月生活费有限，需要知道余额是否充足。学生可能先录入一笔生活费收入，再陆续录入餐饮、学习用品、交通等支出。学生希望系统能按月份筛选流水，避免上个月的记录混入本月统计。如果输错金额或分类，学生希望能直接在菜单里编辑，不必打开 JSON 文件手动修改。

### 3.3 课程评测人员

课程评测脚本会以 subprocess 方式启动程序，通过 stdin 连续发送菜单选项和表单内容，然后检查 stdout、stderr、退出码和 JSON 文件。因此 TUI 不应依赖鼠标、全屏终端、方向键事件或不可脚本化的交互库。简单的“打印菜单 -> 读取一行输入 -> 执行动作 -> 回到菜单”即可满足要求。

## 4. 核心交互体验

### 4.1 默认启动方式

用户运行：

```bash
python -m personal_ledger --file ledger.json
```

程序必须进入交互式文本菜单。启动后 stdout 应包含产品名称和主要操作，例如：

```text
个人记账系统
数据文件: ledger.json
1) 新增账目
2) 查询流水
3) 统计汇总
4) 编辑账目
5) 删除账目
6) 保存并退出
请选择:
```

具体排版可以略有不同，但必须清晰暴露新增、查询、统计、编辑、删除、保存退出六类动作。

### 4.2 会话式操作要求

用户在同一个程序进程中可以连续完成多个操作。示例输入流：

```text
1
2026-06-01
income
salary
5000
monthly salary
1
2026-06-02
expense
food
23.5
lunch
3
2026-06
6
```

程序应按顺序理解为：新增收入、新增支出、查看 2026 年 6 月统计、保存并退出。整个过程不应要求用户重新运行 shell 命令。

### 4.3 关于一次性命令

可以保留可选的一次性命令作为兼容能力，例如 `add`、`list`、`summary` 子命令；但这不是本 benchmark 的核心验收目标。默认只传入 `--file` 时必须启动交互式 TUI。若成品只能通过一次一个命令操作，则不满足本案例要求。

## 5. 功能需求

### F-01 启动应用

当用户执行 `python -m personal_ledger --file ledger.json` 时，系统应：

- 读取指定账本文件。
- 如果文件不存在，视为空账本并正常进入菜单。
- 如果文件存在且内容损坏，应在进入菜单前失败，退出码非 0，并向 stderr 输出包含 `invalid ledger file` 的错误信息。
- 在 stdout 显示产品名称 `个人记账系统` 和六个主菜单动作。
- 在 stdin 到达 EOF 时，不应无限挂起；可以按“保存并退出”处理。

### F-02 新增账目

用户选择 `1` 后，系统进入新增账目表单，依次提示：

1. 日期，格式 `YYYY-MM-DD`。
2. 类型，必须支持英文值 `income` 或 `expense`。可以额外支持中文别名“收入”“支出”，但英文值必须可用。
3. 分类，去除首尾空白后不能为空，例如 `salary`、`food`、`transport`。
4. 金额，必须是大于 0 的数字。
5. 备注，可为空。

新增成功后，系统应立即保存账本文件，并输出：

```text
已新增账目 #<id>: <type> <category> <amount>
```

示例：

```text
已新增账目 #1: income salary 5000.00
```

### F-03 查询流水

用户选择 `2` 后，系统进入查询表单，依次询问：

1. 月份筛选，格式 `YYYY-MM`，允许留空表示全部月份。
2. 类型筛选，`income`、`expense` 或留空表示全部类型。
3. 分类筛选，允许留空表示全部分类。

系统应显示符合条件的流水，输出按日期升序、同日按 ID 升序排列。每条流水格式为：

```text
#<id> <date> <type> <category> <amount> <note>
```

示例：

```text
#2 2026-06-02 expense food 23.50 lunch
```

如果没有符合条件的记录，应输出：

```text
暂无账目
```

### F-04 统计汇总

用户选择 `3` 后，系统要求输入月份，格式为 `YYYY-MM`。月份为必填项，不能留空。

系统只统计该月份的账目，并输出：

```text
收入合计: 5000.00
支出合计: 30.25
余额: 4969.75
food: 23.50
transport: 6.75
```

统计规则：

- `收入合计` 是指定月份内所有 `income` 记录金额之和。
- `支出合计` 是指定月份内所有 `expense` 记录金额之和。
- `余额 = 收入合计 - 支出合计`。
- 分类汇总只统计支出分类，不统计收入分类。
- 分类汇总按分类名升序输出。
- 没有记录时，收入、支出、余额均显示为 `0.00`。

### F-05 编辑账目

用户选择 `4` 后，系统要求输入账目 ID。若 ID 不存在，应输出：

```text
错误: record not found
```

若 ID 存在，系统依次提示新的日期、类型、分类、金额、备注。日期、类型、分类、金额允许留空表示保持原值；备注留空也表示保持原值。编辑成功后，系统应立即保存，并输出：

```text
已更新账目 #<id>: <type> <category> <amount>
```

编辑时必须复用新增账目的校验规则，不能把非法日期、非法类型、空分类或非法金额写入文件。

### F-06 删除账目

用户选择 `5` 后，系统要求输入账目 ID，并进行确认。确认输入 `y`、`Y`、`yes` 或 `是` 时删除；其他输入视为取消。

删除成功后，系统应立即保存，并输出：

```text
已删除账目 #<id>: <type> <category> <amount>
```

若 ID 不存在，应输出：

```text
错误: record not found
```

### F-07 保存并退出

用户选择 `6`、`q`、`quit` 或 `exit` 时，系统保存当前账本并退出，退出码为 0。退出前可以输出：

```text
已保存，退出。
```

## 6. 数据模型

账本文件为 UTF-8 JSON，顶层为数组。每条账目记录包含：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | int | 是 | 自动生成，当前文件内唯一 |
| `date` | str | 是 | 日期，格式 `YYYY-MM-DD` |
| `type` | str | 是 | `income` 或 `expense` |
| `category` | str | 是 | 非空分类，保存去除首尾空白后的值 |
| `amount` | str | 是 | 两位小数字符串，例如 `"23.50"` |
| `note` | str | 是 | 备注，可为空字符串 |

示例：

```json
[
  {
    "id": 1,
    "date": "2026-06-01",
    "type": "income",
    "category": "salary",
    "amount": "5000.00",
    "note": "monthly salary"
  },
  {
    "id": 2,
    "date": "2026-06-02",
    "type": "expense",
    "category": "food",
    "amount": "23.50",
    "note": "lunch"
  }
]
```

## 7. 数据持久化规则

- 文件不存在时，系统视为空账本。
- 保存时使用 UTF-8 编码、两个空格缩进。
- 新 ID 使用当前最大 ID 加一，不复用已删除记录的 ID。
- 每次新增、编辑、删除成功后都应立即保存，避免异常退出导致数据丢失。
- 程序重新启动后，必须能加载上一次保存的数据。
- 金额保存为字符串，不保存为浮点数。
- 支出不以负数保存，而是通过 `type=expense` 表示。

## 8. 校验和错误处理

### 8.1 表单级错误

表单级错误应输出到 stdout，然后回到主菜单继续接受输入，不能直接崩溃。输出文本必须包含以下稳定错误短语，便于用户识别和自动化测试：

| 场景 | 稳定错误短语 |
| --- | --- |
| 日期不是合法 `YYYY-MM-DD` | `invalid date` |
| 月份不是合法 `YYYY-MM` | `invalid month` |
| 金额无法解析或小于等于 0 | `invalid amount` |
| 类型不是 `income` 或 `expense` | `invalid type` |
| 必填字段为空 | `required field missing` |
| 账目 ID 不存在 | `record not found` |
| 未知菜单选项 | `unknown option` |

建议输出格式为 `错误: <稳定错误短语>`，例如：

```text
错误: invalid amount
```

### 8.2 启动级错误

如果账本文件不是合法 JSON、JSON 顶层不是数组，或记录结构无法解析，系统应在进入菜单前失败：

- 退出码非 0。
- stderr 包含 `invalid ledger file`。
- stdout 不应显示主菜单。
- 不应覆盖原始损坏文件。

## 9. 非功能需求

- Python 版本：Python 3.11+。
- 依赖：仅使用 Python 标准库。
- 可测试性：TUI 必须可由 stdin/stdout 驱动，不依赖 curses、鼠标、全屏刷新或外部服务。
- 可维护性：建议分层组织代码，将 TUI、业务逻辑、数据模型、存储逻辑分开。
- 可移植性：路径通过 `pathlib.Path` 或等价方式处理，兼容 Windows、macOS 和 Linux。

## 10. 非目标

- 不支持多用户登录。
- 不支持云同步。
- 不支持图表或图形界面。
- 不支持预算提醒、周期账单或账户间转账。
- 不要求 CSV 导入导出。若实现 CSV 导出，也不能影响本 PRD 中的 TUI 行为和 JSON 持久化要求。

# 学生成绩管理系统 PRD

## 1. 产品背景

学校、培训机构和课程团队在日常教学中需要持续维护学生、课程和成绩数据。很多教师仍然使用电子表格记录成绩：新增学生时手动插入行，录入成绩时手动查找课程列，修改成绩时担心覆盖错误，期末统计时再用公式计算均分、最高分、最低分和排名。对于人数不多的班级，电子表格可以勉强使用；但一旦课程较多、成绩修改频繁、教师需要随时查询某个学生或某门课程的情况，手工维护就容易出现重复学号、课程编号混乱、成绩越界、统计口径不一致等问题。

本产品希望提供一个轻量但完整的学生成绩管理系统，让教师或班级管理员可以在一个类似真实软件的交互界面中完成学生管理、课程管理、成绩录入、成绩修改、查询、统计、排名和数据保存。系统不应要求用户记忆大量一次性命令，也不应要求用户手动发送 HTTP 请求；用户启动程序后，应通过菜单和表单持续完成多个操作。

## 2. 产品目标

1. 帮助教师在本地快速维护一个班级或课程组的学生成绩数据。
2. 提供清晰的 TUI 菜单，让用户像使用正常应用一样连续操作。
3. 支持学生、课程、成绩三类核心数据的增删改查。
4. 自动完成常见统计分析，包括学生平均分、课程均分、最高分、最低分和排名。
5. 使用本地 JSON 文件持久化数据，保证关闭程序后重新打开仍能继续使用。
6. 对重复编号、缺失字段、分数越界和无效输入给出友好错误提示，避免错误数据进入系统。

## 3. 目标用户

### 3.1 任课教师

任课教师需要为一门或多门课程录入学生成绩，查看某门课程的成绩分布，快速找出最高分、最低分和排名靠前的学生。教师通常希望少写命令，能通过菜单一步步完成操作。

### 3.2 教务人员

教务人员负责维护班级学生名单和课程清单。他们更关心数据规范性，例如学号是否重复、课程编号是否重复、必填字段是否为空，以及保存后的数据是否能重新加载。

### 3.3 班级管理员或助教

班级管理员、助教可能在成绩发布前协助老师检查成绩。他们需要按学生查询该学生所有课程成绩，按课程查询所有学生成绩，并在发现录入错误时及时修改或删除成绩。

## 4. 使用范围

### 4.1 本期范围

- 本地单机运行。
- Python 标准库实现。
- TUI 菜单交互。
- 学生信息管理。
- 课程信息管理。
- 成绩录入、修改、删除。
- 按学生查询成绩。
- 按课程查询成绩。
- 学生平均分、课程统计、总分统计。
- 按课程排名、按总分排名。
- JSON 文件保存与加载。

### 4.2 非目标

- 不开发 Web 前端。
- 不开发数据库服务。
- 不提供用户登录、权限控制和多人协作。
- 不要求图表可视化。
- 不要求导入 Excel 或 CSV。
- 不要求处理学分绩点、补考、缓考等复杂教务规则。

## 5. 运行和交互要求

系统必须提供如下入口：

```bash
python -m student_gradebook
```

同时必须支持通过 `--file` 指定数据文件：

```bash
python -m student_gradebook --file gradebook.json
```

启动后，程序必须进入持续交互式 TUI，而不是执行单个命令后退出。用户可以在同一次会话中连续新增学生、新增课程、录入成绩、查询成绩、查看统计、保存数据并退出。

主菜单应包含以下选项，编号必须稳定：

```text
学生成绩管理系统
1. 新增学生
2. 新增课程
3. 录入成绩
4. 修改成绩
5. 删除成绩
6. 按学生查询
7. 按课程查询
8. 成绩统计
9. 排名展示
10. 保存数据
11. 重新加载
0. 退出
```

用户输入未知菜单编号时，系统应提示 `未知选项`，然后回到主菜单继续运行。

## 6. 核心业务流程

### 6.1 首次建档流程

1. 用户启动系统。
2. 系统读取指定 JSON 数据文件；如果文件不存在，则创建空成绩簿。
3. 用户通过“新增学生”录入学生。
4. 用户通过“新增课程”录入课程。
5. 用户通过“录入成绩”为某个学生在某门课程下录入分数。
6. 用户通过“保存数据”将当前成绩簿写入 JSON 文件。
7. 用户退出系统。

### 6.2 日常成绩维护流程

1. 用户启动系统并自动加载历史数据。
2. 用户按学生或按课程查询成绩，确认当前数据。
3. 如果成绩录入错误，用户进入“修改成绩”输入学号、课程编号和新分数。
4. 如果某条成绩不应存在，用户进入“删除成绩”输入学号和课程编号。
5. 用户再次查询或查看统计，确认修改已经生效。
6. 用户保存数据。

### 6.3 统计和排名流程

1. 用户进入“成绩统计”。
2. 用户可以查看单门课程统计，也可以查看全局汇总。
3. 单门课程统计包含课程平均分、最高分、最低分和人数。
4. 用户进入“排名展示”。
5. 用户可以选择按某门课程分数排名，也可以选择按学生总分排名。
6. 系统按分数从高到低输出排名，便于教师快速了解班级成绩情况。

## 7. 功能需求

### F1. 学生信息管理

用户选择菜单 `1` 后，系统依次要求输入：

1. 学号 `student_id`
2. 姓名 `name`
3. 班级 `class_name`

规则：

- 学号不能为空。
- 姓名不能为空。
- 班级可以为空；为空时保存为空字符串。
- 学号是学生唯一标识，不能重复。
- 新增成功后输出 `已新增学生 <student_id> <name>`。
- 学号为空时输出 `学号不能为空`。
- 姓名为空时输出 `姓名不能为空`。
- 学号重复时输出 `学号已存在`。

### F2. 课程信息管理

用户选择菜单 `2` 后，系统依次要求输入：

1. 课程编号 `course_code`
2. 课程名称 `name`
3. 学分 `credit`

规则：

- 课程编号不能为空。
- 课程名称不能为空。
- 学分可以为空；为空时按 `0` 保存。
- 学分如果填写，必须是非负数字。
- 课程编号是课程唯一标识，不能重复。
- 新增成功后输出 `已新增课程 <course_code> <name>`。
- 课程编号为空时输出 `课程编号不能为空`。
- 课程名称为空时输出 `课程名称不能为空`。
- 课程编号重复时输出 `课程编号已存在`。
- 学分无效时输出 `学分必须是数字`。

### F3. 成绩录入

用户选择菜单 `3` 后，系统依次要求输入：

1. 学号 `student_id`
2. 课程编号 `course_code`
3. 分数 `score`

规则：

- 学号不能为空。
- 课程编号不能为空。
- 分数不能为空。
- 学号必须已存在。
- 课程编号必须已存在。
- 分数必须是 0 到 100 之间的数字，允许小数。
- 同一个学生同一门课程只能存在一条成绩。
- 录入成功后输出 `已录入成绩 <student_id> <course_code> <score>`，分数保留两位小数。
- 成绩已存在时输出 `成绩记录已存在`，不能覆盖原成绩；需要修改时应使用“修改成绩”。

### F4. 成绩修改

用户选择菜单 `4` 后，系统依次要求输入：

1. 学号 `student_id`
2. 课程编号 `course_code`
3. 新分数 `score`

规则：

- 需要修改的成绩记录必须存在。
- 新分数必须是 0 到 100 之间的数字。
- 修改成功后输出 `已修改成绩 <student_id> <course_code> <score>`，分数保留两位小数。
- 找不到成绩记录时输出 `成绩记录不存在`。

### F5. 成绩删除

用户选择菜单 `5` 后，系统依次要求输入：

1. 学号 `student_id`
2. 课程编号 `course_code`

规则：

- 需要删除的成绩记录必须存在。
- 删除成功后输出 `已删除成绩 <student_id> <course_code>`。
- 找不到成绩记录时输出 `成绩记录不存在`。

### F6. 按学生查询

用户选择菜单 `6` 后，输入学号。

系统应输出：

- 学生基本信息。
- 该学生所有课程成绩。
- 该学生平均分。

输出格式应包含以下信息：

```text
学生 <student_id> <name> <class_name>
<course_code> <course_name> <score>
学生平均分: <average>
```

如果该学生没有任何成绩，仍应输出学生信息，并输出 `暂无成绩`。

### F7. 按课程查询

用户选择菜单 `7` 后，输入课程编号。

系统应输出：

- 课程基本信息。
- 该课程下所有学生成绩。
- 课程平均分。
- 课程最高分。
- 课程最低分。

输出格式应包含以下信息：

```text
课程 <course_code> <course_name>
<student_id> <student_name> <score>
课程平均分: <average>
最高分: <student_id> <student_name> <score>
最低分: <student_id> <student_name> <score>
```

如果课程没有任何成绩，应输出 `暂无成绩`。

### F8. 成绩统计

用户选择菜单 `8` 后，系统进入统计子菜单：

```text
1. 课程统计
2. 总体统计
```

选择 `1` 时，用户输入课程编号，系统输出该课程人数、平均分、最高分和最低分。

选择 `2` 时，系统输出：

- 学生人数。
- 课程数量。
- 成绩记录数量。
- 全部成绩平均分。

如果用户输入其他统计选项，应输出 `无效统计方式` 并回到主菜单。

### F9. 排名展示

用户选择菜单 `9` 后，系统进入排名子菜单：

```text
1. 按课程排名
2. 按总分排名
```

选择 `1` 时，用户输入课程编号，系统按该课程分数从高到低输出排名：

```text
#1 <student_id> <student_name> <score>
#2 <student_id> <student_name> <score>
```

选择 `2` 时，系统按学生总分从高到低输出排名：

```text
#1 <student_id> <student_name> 总分 <total> 平均分 <average>
#2 <student_id> <student_name> 总分 <total> 平均分 <average>
```

规则：

- 课程排名按单门课程分数降序。
- 总分排名按学生所有已录入课程分数之和降序。
- 如果总分相同，再按平均分降序。
- 如果仍然相同，再按学号升序。
- 没有任何可排名成绩时输出 `暂无成绩`。
- 输入无效排名方式时输出 `无效排名方式`。

### F10. 保存数据

用户选择菜单 `10` 后，系统将当前内存中的学生、课程和成绩写入 JSON 文件。

保存成功后输出：

```text
保存成功
```

### F11. 重新加载

用户选择菜单 `11` 后，系统从当前 JSON 文件重新加载数据，替换内存中的数据。

重新加载成功后输出：

```text
重新加载成功
```

如果文件不存在，则加载为空成绩簿，并输出 `重新加载成功`。

## 8. 数据持久化要求

系统使用 JSON 文件保存数据。通过 `--file` 指定文件路径；如果未指定，则默认使用当前工作目录下的 `gradebook.json`。

JSON 顶层结构必须包含：

```json
{
  "students": [
    {
      "student_id": "S001",
      "name": "Ada",
      "class_name": "Class 1"
    }
  ],
  "courses": [
    {
      "course_code": "CS101",
      "name": "Python",
      "credit": 3.0
    }
  ],
  "grades": [
    {
      "student_id": "S001",
      "course_code": "CS101",
      "score": 95.0
    }
  ]
}
```

要求：

- 所有字符串字段在保存前去除首尾空白。
- 分数保存为数字。
- 文件使用 UTF-8 编码。
- 保存时应写出可读 JSON，建议使用缩进。
- 启动时如果 JSON 文件不存在，应使用空数据继续运行。
- 启动时如果 JSON 文件存在但格式非法，程序应向 stderr 输出 `成绩文件无效`，返回非 0，并且不能进入主菜单。

## 9. 成绩计算规则

### 9.1 学生平均分

学生平均分等于该学生所有已录入课程成绩的算术平均值。

```text
学生平均分 = 学生所有成绩之和 / 该学生成绩数量
```

显示时保留两位小数。

### 9.2 学生总分

学生总分等于该学生所有已录入课程成绩之和。总分用于“按总分排名”。

### 9.3 课程平均分

课程平均分等于该课程所有学生成绩的算术平均值。

### 9.4 课程最高分和最低分

课程最高分和最低分都在该课程已有成绩中计算。如果分数并列：

- 最高分取学号字典序更小的学生。
- 最低分取学号字典序更小的学生。

### 9.5 数字格式

所有展示给用户的分数、平均分和总分都保留两位小数，例如 `95.00`、`87.50`。

## 10. 错误处理要求

系统应尽量在当前操作内提示错误，然后回到主菜单继续运行，不能因为普通输入错误直接崩溃退出。

必须覆盖的错误包括：

- 学号为空。
- 姓名为空。
- 课程编号为空。
- 课程名称为空。
- 学号重复。
- 课程编号重复。
- 学生不存在。
- 课程不存在。
- 成绩记录已存在。
- 成绩记录不存在。
- 分数为空。
- 分数不是数字。
- 分数小于 0 或大于 100。
- 菜单选项无效。
- 统计方式无效。
- 排名方式无效。
- JSON 文件损坏。

错误提示应使用简短、明确的中文，例如 `学号不能为空`、`课程不存在`、`成绩必须在 0 到 100 之间`。

## 11. 交互体验要求

- 程序应在每次操作后回到主菜单，除非用户选择退出。
- 菜单编号要稳定，不能因为数据变化而变化。
- 列表输出要适合终端阅读，至少包含编号、姓名或课程名、分数等关键字段。
- 用户不需要记忆复杂命令。
- 用户不需要手动编辑 JSON 文件。
- 用户不需要手动发送 HTTP 请求。
- TUI 可以使用纯文本菜单实现，不要求 curses、Rich 或 Textual。

## 12. 验收重点

验收会重点检查：

- 入口是否为可持续交互的 TUI。
- 是否能新增学生和课程。
- 是否能录入、修改、删除成绩。
- 是否能按学生和课程查询。
- 是否能计算学生平均分。
- 是否能计算课程平均分、最高分、最低分。
- 是否能按课程和总分排名。
- 是否能保存并重新加载 JSON 数据。
- 是否能处理重复编号、分数越界、缺失字段和无效菜单输入。

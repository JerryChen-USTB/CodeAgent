# 学生成绩管理系统用户故事

## 1. 用户故事总览

学生成绩管理系统面向日常教学管理场景。用户不是程序员，不能要求他们每次操作都输入复杂命令，也不能要求他们手动编辑 JSON 文件。系统应让用户启动程序后，通过清晰的菜单和表单一步步完成工作。

本系统的典型用户包括任课教师、教务人员、班级管理员和助教。下面的用户故事用自然语言描述他们在真实工作中的需求、动机和期望结果。

## 2. 任课教师：首次建立成绩簿

王老师刚接手一个新班级，需要为“Python 程序设计”和“数据结构”两门课建立本地成绩簿。她希望打开程序后，先看到一个清楚的主菜单，而不是一串需要记忆的命令。

王老师选择“新增学生”，按照提示输入学生的学号、姓名和班级。录入成功后，系统立即提示她已经新增了哪个学生。她继续新增第二名、第三名学生。录入过程中，如果她不小心把学号留空，系统应该告诉她“学号不能为空”，并且不要创建无效学生；如果她重复输入了已经存在的学号，系统应该告诉她“学号已存在”，避免同一名学生出现两次。

学生名单录入完成后，王老师选择“新增课程”。她输入课程编号、课程名称和学分。系统应保证课程编号唯一。如果课程编号重复，系统要提示“课程编号已存在”。王老师不希望系统因为一个错误输入而退出，她希望改正后可以继续使用。

完成学生和课程建档后，王老师选择“保存数据”。系统把成绩簿保存到指定 JSON 文件，并提示“保存成功”。第二天她重新打开程序时，系统可以自动读取这个文件，继续展示昨天建立的学生和课程数据。

## 3. 任课教师：批量录入一次考试成绩

期中考试结束后，王老师需要录入“Python 程序设计”课程成绩。她希望在同一次程序会话中连续录入多名学生的成绩。

她选择“录入成绩”，输入学生学号、课程编号和分数。系统检查学生是否存在、课程是否存在、分数是否在 0 到 100 之间。如果全部正确，系统输出类似“已录入成绩 S001 CS101 95.00”的提示，让王老师确认录入成功。

如果王老师输错分数，例如输入 `101`，系统应提示“成绩必须在 0 到 100 之间”；如果输入 `abc`，系统应提示“成绩必须是数字”。这些错误都不应该写入成绩簿。

如果王老师重复录入同一名学生同一门课程的成绩，系统应提示“成绩记录已存在”。这样可以防止误覆盖。需要改分时，王老师应进入“修改成绩”完成。

## 4. 助教：修改和删除错误成绩

助教小李在复核成绩时发现，学生 S002 的 CS101 成绩从 75 分更正为 80 分。小李不想重新建立学生和课程，只需要进入“修改成绩”，输入学号、课程编号和新分数。

系统应先确认该成绩记录已经存在，再更新分数。修改成功后，系统输出“已修改成绩 S002 CS101 80.00”。如果小李输入了不存在的学生和课程组合，系统应提示“成绩记录不存在”，不能默默创建一条新记录。

另一次复核中，小李发现学生 S001 的 MATH 成绩是误录的，因为这名学生没有选修该课程。小李进入“删除成绩”，输入学号和课程编号。系统删除该成绩记录，并输出“已删除成绩 S001 MATH”。删除后，小李再按学生查询 S001 时，不应再看到 MATH 成绩。

## 5. 班级管理员：按学生查询成绩

班级管理员需要答复学生关于成绩的咨询。学生 Ada 想知道自己目前已经录入了哪些课程成绩，以及平均分是多少。

管理员选择“按学生查询”，输入 Ada 的学号 S001。系统输出学生基本信息，例如学号、姓名和班级；然后列出该学生所有课程成绩，包括课程编号、课程名称和分数；最后输出“学生平均分: 95.00”这样的汇总信息。

如果某名学生还没有任何成绩，系统仍然要能显示学生基本信息，并提示“暂无成绩”。这可以帮助管理员区分“学生不存在”和“学生存在但还没有成绩”。

## 6. 任课教师：按课程查询成绩

王老师需要查看 CS101 课程目前的成绩录入情况。她选择“按课程查询”，输入课程编号 CS101。

系统输出课程基本信息，然后列出所有已录入该课程成绩的学生。每一行应包含学号、姓名和分数。列表后方应展示课程平均分、最高分和最低分。

例如，S001 得 95 分，S002 得 80 分时，系统应显示课程平均分为 87.50，最高分为 S001 Ada 95.00，最低分为 S002 Bob 80.00。

如果课程存在但还没有任何成绩，系统应提示“暂无成绩”，而不是报错退出。

## 7. 教务人员：查看课程统计

教务人员需要快速了解某门课程的整体表现。他选择“成绩统计”，再选择“课程统计”，输入课程编号。

系统应展示该课程的成绩人数、课程平均分、最高分和最低分。教务人员不需要手动计算，也不需要导出文件后再使用电子表格公式。统计结果要和按课程查询中的结果保持一致。

如果课程编号不存在，系统应提示“课程不存在”；如果统计方式输入错误，系统应提示“无效统计方式”并返回主菜单。

## 8. 教务人员：查看总体统计

学期末，教务人员需要知道当前成绩簿中一共有多少学生、多少课程、多少条成绩记录，以及所有成绩的整体平均水平。

他选择“成绩统计”，再选择“总体统计”。系统输出学生人数、课程数量、成绩记录数量和全部成绩平均分。这个信息可以帮助教务人员判断数据是否录入完整，例如学生人数和课程数量是否符合预期。

如果当前没有任何成绩记录，系统应输出人数和课程数量，并提示“暂无成绩”或将整体平均分显示为 `0.00`，但不能崩溃。

## 9. 任课教师：按课程排名

王老师想查看 CS101 课程的排名。她选择“排名展示”，再选择“按课程排名”，输入课程编号 CS101。

系统按照该课程成绩从高到低展示排名：

```text
#1 S001 Ada 95.00
#2 S002 Bob 80.00
```

如果两名学生分数相同，系统应按学号升序排序，保证排名结果稳定。王老师希望每次查看同一份数据时，排名顺序都一致。

## 10. 教务人员：按总分排名

教务人员需要查看所有学生按总分的综合排名。他选择“排名展示”，再选择“按总分排名”。

系统计算每个学生所有已录入课程成绩之和作为总分，同时计算平均分，并按总分从高到低展示：

```text
#1 S001 Ada 总分 183.00 平均分 91.50
#2 S002 Bob 总分 160.00 平均分 80.00
```

如果总分相同，应按平均分降序排序；如果平均分也相同，应按学号升序排序。这样排名结果既符合直觉，也便于验证。

## 11. 班级管理员：保存和重新加载

班级管理员完成一轮成绩录入后，选择“保存数据”。系统将学生、课程和成绩写入 JSON 文件。管理员关闭程序后再次打开，并指定同一个数据文件，应能继续查询之前录入的数据。

如果管理员在一次会话中做了一些实验性修改，又想放弃这些未保存修改，可以选择“重新加载”。系统从 JSON 文件重新读取数据，替换当前内存中的成绩簿，并提示“重新加载成功”。

如果 JSON 文件被手动破坏，例如内容不是合法 JSON，系统启动时应向错误输出提示“成绩文件无效”，返回非 0，并且不要进入主菜单。这样用户能及时发现文件损坏，而不是在错误数据上继续操作。

## 12. 交互体验故事

教师和管理员希望这个工具像一个正常小软件，而不是一次执行一个命令的脚本。因此系统需要满足以下体验：

- 启动后显示标题“学生成绩管理系统”。
- 每次操作完成后回到主菜单。
- 用户可以连续完成多个操作。
- 菜单编号稳定。
- 表单提示清楚。
- 出错时显示中文错误信息。
- 普通输入错误不会导致程序崩溃。
- 保存和重新加载都有明确反馈。

当读者或测试程序通过标准输入连续输入菜单编号和字段值时，系统应能稳定处理这些输入。这既支持人工演示，也支持自动化 oracle 测试。
